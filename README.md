# AntiSleep

**電源ボタンをONにするとMac本体をスリープさせず、画面は消灯できるmacOSアプリです。**
Caps Lockには連動しません。初期設定ではOFFで起動します。
パネル下部の「起動時にON」で、次回以降の起動状態を設定できます。

## 動作

| 操作・状態 | 動作 |
| --- | --- |
| アプリを起動 | 保存した起動時設定でメニューバーに常駐。初期値OFFでは電源設定を変更しない |
| メニューバーの点を左クリック | 大きな電源ボタンを持つパネルを開閉 |
| 点を右クリック | 「終了」メニューを表示 |
| パネル右上の× | 設定を復元し、スリープ防止と復元監視を止めてアプリを終了 |
| 電源ボタンをON | 無操作スリープ・ふた閉じスリープを防止。両方の適用確認後に点が緑になる |
| 電源ボタンをOFF | ONにする直前の設定へ戻し、防止要求を解除。アプリは常駐を継続 |
| OFF・保護の適用未確認 | 点は灰色。適用未確認時はパネルに理由を表示 |
| 「起動時にON」を変更 | 設定を保存し、次回のアプリ起動時から適用。現在のON/OFFは変更しない |
| 次回起動 | 「起動時にON」の設定で開始。直前の保護状態には連動しない |
| ONでふたを閉じる | 本体の保護を維持し、外部画面を含む画面を明示的に消灯 |
| 画面の自動消灯 | 許可。点灯維持の要求は登録しない |
| パネルの外側をクリックして閉じる | ON/OFFは変えずに常駐を継続 |
| 終了 | ONなら変更前の設定を復元して終了。OFFなら設定に触れない |
| ON中に保護設定が外部から解除された | 2秒間隔の確認で再適用 |
| ON中に異常終了 | 別プロセスが親の終了を検出し、変更前の設定へ復元 |

OFF・終了時の復元に失敗した場合はONを維持し、失敗を表示します。
復元監視が起動する前にシステム設定を書き換えることはありません。
通常起動・定期確認ではパネルを勝手に前面へ出しません。

## 使い方

macOS 14以降が必要です。今回の配布ビルドはApple Silicon用です。
配布アプリの実行にSwiftや追加のランタイムは不要です。

1. `AntiSleep.app`をアプリケーションフォルダなどに置いて開きます。最初は灰色の点（OFF）です。
2. 旧版Capsomniaが動作している場合は終了します。同時実行時は競合を表示します。
3. メニューバーの点をクリックし、中央の電源ボタンでONにします。
4. ヘルパーが未設定の場合は「ヘルパーを設定…」を押し、macOSの管理者認証を行います。
5. パネルにON、メニューバーに緑の点が表示されたことを確認します。
6. 保護を止める場合は再び電源ボタンを押します。アプリ自体を終了する場合は、パネル右上の×を押すか、点を右クリックして「終了」を選びます。
7. 次回からONで起動したい場合は、下部の「起動時にON」を有効にします。この操作では現在の保護状態は変わりません。OFFに戻すと、次回からOFFで起動します。

すでにCapsomniaの正規ヘルパーが設定されていれば、その固定操作を利用できます。
ただしCapsomnia本体との同時実行には対応しません。
画面の自動消灯時間、充電設定、Caps Lock、ログイン時の自動起動設定は変更しません。

## 権限と復元

無操作スリープはIOKitの`PreventUserIdleSystemSleep`で防止します。
ふた閉じ保護は管理者権限で`pmset -a disablesleep 1`を適用します。
画面の点灯を維持する`PreventUserIdleDisplaySleep`は登録しません。

同梱ヘルパーの管理者操作は、固定された`on`・`off`・`display-sleep`だけです。
初回認証では`/Library/PrivilegedHelperTools/anti-sleep-pmset`と、
その3操作だけを許可する`/etc/sudoers.d/anti-sleep`を配置します。
任意のコマンドや任意の`pmset`引数を管理者権限で実行する口は設けません。

OFFへの切り替え・通常終了・親プロセスだけの異常終了では、ONにする直前の`SleepDisabled`へ戻します。
通常終了では、設定の実値・無操作スリープ防止要求の解除・復元監視プロセスの停止を確認し、
確認できなければ終了を中止して再試行できる状態を維持します。
設定コマンドが失敗応答を返しても設定だけ変更される場合を考慮し、復元対象として追跡します。
設定変更は監視プロセス内で直列に実行し、本体が変更途中で落ちても変更完了後に復元します。
異常終了時の監視はTERM・INT・HUPで終了せず、復元後の実値が元に戻るまで、失敗後5秒待って再試行します。
ヘルパーの削除・権限変更などで復元不能な場合は監視が残るため、ヘルパーの修復が必要です。
元から`SleepDisabled=1`だった場合、その既存設定を維持し、他のアプリの防止要求は解除しません。
OSクラッシュ、強制電源断、監視プロセスまで同時に強制終了した場合は復元を保証できません。
その場合、元の設定が通常スリープだったMacでは次の操作で戻せます。

```sh
sudo pmset -a disablesleep 0
```

スリープ防止は実行中アプリの異常終了、通信断、バッテリー切れを防ぐものではありません。
閉じたまま処理を続ける場合も、放熱できる場所で使用してください。

## 開発

Command Line ToolsのSwift 5.9以降でビルドできます。外部パッケージに依存しません。
XCTestがないCommand Line Tools環境でも、専用の検証ランナーで状態遷移を確認できます。

```sh
swift run AntiSleepChecks
zsh scripts/build-app.sh
```

生成物は`dist/AntiSleep.app`です。ローカルビルドはアドホック署名です。
AppleのDeveloper ID署名・公証は付いていません。

`Assets/AppIcon.png`は、採用した「内側の発光」案を透過処理した製品用の固定素材です。
再ビルド時に同じアイコンを同梱するためGitで管理し、期限のあるCI artifactには依存しません。
ビルド時に16〜1024pxの各解像度を含む`.icns`へ変換します。
ガラスと発光は静止画の表現で、Icon Composerの動的なLiquid Glass形式ではありません。

画面の構成だけを確認する場合は、電源設定変更を行わないプレビューを使えます。
プレビュー内で起動時トグルを操作しても、本番の起動時設定は変更しません。
画像出力プレビューはメニューバー項目を作らず、本番の表示設定に影響しません。

```sh
dist/AntiSleep.app/Contents/MacOS/AntiSleep --preview
```

検証結果は[docs/verification.md](docs/verification.md)に記載します。
起動時設定の実機検証は、実行中のAntiSleepを終了し、`SleepDisabled=0`の状態で次を実行します。
設定は検証終了時に元へ戻します。従来の切り替え・メニューバー検証は「起動時にON」をOFFにして実行します。

```sh
python3 scripts/verify-startup.py /Applications/AntiSleep.app test-results/startup/report.json
```

ログは`~/Library/Logs/AntiSleep/`にUTC時刻で保存します。

## ヘルパーの削除

AntiSleepを正常終了してから、不要であれば以下を削除します。
既存Capsomniaのヘルパー・設定には手を加えません。

```sh
sudo rm /etc/sudoers.d/anti-sleep /Library/PrivilegedHelperTools/anti-sleep-pmset
```

## 背景

[Capsomnia](https://github.com/fuji-mak/Capsomnia)の起動中にも処理が停止した調査を契機に、
キーの状態に左右されないアプリとして新規作成しています。
Capsomniaの公式版・公式フォークではありません。
