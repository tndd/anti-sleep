# 検証記録

2026年10月15日。Apple Silicon Mac / macOS 15.8.1で確認。

## 0.2.3：緑の点とガラスのアプリアイコン

採用した「内側の発光」案を製品用の透過PNGとして保存し、16〜1024pxを含む
`.icns`へ変換してアプリに同梱する。メニューバーとパネル上部は同じ緑の点に統一。
適用確認済みのONだけを緑、OFF・適用未確認は灰色で表示する。
macOS 14以降で使える静止アイコンで、動的なLiquid Glass形式ではない。

- 状態遷移23項目、Releaseビルド、アプリとヘルパーのdeep / strict署名検証が成功。
- PNGの1024px・透過外周・不透明な中心と、バンドルのアイコン設定を確認。
- 実際の`.icns`と同じ描画コードによる点を、明暗背景・実寸と拡大で画像化して目視確認。
- 出荷用アプリのOFF/ON画像プレビューを目視し、パネル上部の点と配置を確認。
- 検証用ビルドのプレビューON/OFFで、アプリ自身のイベントキューへ左右クリックを投入。
  開閉・右クリック終了・常駐項目の可視性を確認。電源設定は変更しない条件で実施。
- `/Applications/AntiSleep.app`でメニューバー可視性検証を実施。
  起動OFF、右側配置、画像プレビューが本番の項目を隠さないことを確認。
- 正式版を通常起動し、直後・2秒後・8秒後のOFF常駐を確認。
  NSWorkspaceが正式版から取得したアイコンも画像で目視確認した。
- 同じbundle IDを持つ作業用コピー2件を登録解除してゴミ箱へ移動。
  Spotlightのメタデータ検索結果が`/Applications/AntiSleep.app`の1件になったことを確認。

今回はアイコンとビルド資材の変更のため、電源設定・ふた閉じ・異常終了時復元の
実システム試験は再実施していない。画面全体のスクリーンショットや物理マウス操作と、
アプリ自身のビュー画像・検証イベントによる確認は区別する。

## 0.2.2：電源画面の簡素化と右クリック終了

電源画面下部の「画面を消灯」「終了」と区切り線を削除し、通常時の補足注記も除いた。
パネルは電源ボタン・ON/OFF状態・状態説明を中心にし、縦寸法は内容から算出する。
上下の余白を20ptで揃え、状態説明も固定高さをやめて文字の行数に合わせる。
ヘルパーが必要な場合の設定ボタンは、その状態のときだけ表示する。
稲妻の左クリックでパネルを開閉、右クリックで「終了」だけのメニューを表示する。
右クリックは開いている電源パネルを閉じ、メニューから従来の復元付き終了処理へ進む。

OFF/ONのビューをPNG化して目視確認。状態遷移23項目・Releaseビルド・署名を確認した。
入力経路の確認には、出荷用ソースに試験開始処理を一時的に追加した検証用ビルドを使用。
AppKitのイベントキューへ検証用アプリ自身の左/右マウスイベントを投入し、
左クリックで開く・再クリックで閉じる・右クリックで終了メニューだけを出す動作を確認した。
OFF時は左クリックの開閉と右クリック、ON時は起動後の右クリックを確認した。
終了項目の実actionを選択し、OFF・ONの両方で正常終了し、
ONではSleepDisabled=0へ復元して防止要求を残さないことを確認した。
画像プレビュー後のメニューバー可視性と右側配置の検証も成功した。
物理的なマウス操作による確認とは区別する。電源制御・ふた閉じ処理は変更していないため、
物理的なふた操作・強制終了の再試験は省略した。

## 0.2.1：メニューバーのアイコンが左端へ消える問題

画像プレビューでNSStatusItem.isVisible=falseを設定すると、AppKitが自動採番した
Item-0の非表示設定を保存していた。本番も同じ自動名を使用していたため、
通常起動時に非表示状態を引き継いだ。実機でisVisible=false・x=0を
起動直後・2秒後・8秒後に確認し、修正前の検証スクリプトが失敗することを確認した。
0.2.0ではアプリの常駐とパネル非表示だけを確認し、メニューバー自体の可視性を見落としていた。

画像出力ではメニューバー項目を作らず、本番は専用名AntiSleepで表示を明示する。
対話プレビューは別名AntiSleepPreviewを使う。他アプリの配置やシステム全体の設定は変更しない。

検証：23項目・Releaseビルド・署名検証に加え、verify-menu-bar.pyで
通常起動の可視性と右側配置、OFF/ON画像プレビューで項目を作らないこと、
プレビュー後も本番アイコンが右側に残ること、OFFとパネル非表示の維持を確認した。
AppKitの初期配置前は一時的にx=0になるため、右側配置は2秒後・8秒後に確認する。
OFF→ON→OFF→ONと再起動でも可視性・右側配置を検証した。
電源制御・ふた閉じ処理は今回変更していないため、物理的なふた操作や強制終了試験は再実施していない。

| 配布ZIP | 破損検査とアプリ本体の格納を確認 |

実システムの検証には、すでに導入済みのCapsomnia用固定ヘルパーを使用。
旧版Capsomnia本体は正常終了させ、設定の競合を避けた。
仮のcaffeinateはAntiSleepの防止要求を確認してから終了した。

初回の終了検証で、設定の復元後も終了応答を待ちプロセスが残る問題があった。
終了通知元のイベントループに依存せず、復元と監視停止を確認して終了するよう修正し、
通常終了・強制終了を含む実機検証を再実行して成功した。

画面収録によるOSウィンドウ画像の取得は、画面収録権限がなく失敗した。
そのため、他アプリやデスクトップを取得せず、アプリ自身のビュー描画を検査した。

検証・更新による再起動のたびにウィンドウを前面へ出していたため、通常起動を
メニューバーへの常駐だけに変更した。表示が必要な検証は明示的な起動オプションで開く。
更新中も一時的な防止要求で保護をつなぎ、更新後のアプリ自身の保護を確認してから解除した。

## 0.1.0の最後の実機試験

ユーザーによる実際のふた閉じ・開閉操作で検証した。
起動中のAntiSleepを再起動せず、caffeinateが存在しない状態で測定した。
ふた閉じをIORegistryから実検出し、実際の画面消灯・点灯と本体スリープの記録をpmsetで確認した。

- ふた閉じ時間：517.266秒。
- ふた閉じ中の連続消灯：517.000秒。
- 測定のハートビート：927回、最大間隔1.166秒。
- 本体のスリープ記録：0件。
- ふたを開いた後：開状態への復帰、アプリ自身の防止要求、SleepDisabled=1を確認。

時間の計測には、システムスリープ中も進むmach_continuous_timeを使用した。
測定間隔が3秒以上空いた場合、ふた閉じ・連続消灯が70秒未満だった場合、
保護が解除された場合、本体スリープの記録がある場合は不合格とする。
先に点灯してしまった消灯試験は不採用のままとし、この実機試験で保留していた2項目を回収した。

## 再現方法

```sh
swift run AntiSleepChecks
zsh scripts/build-app.sh
```

以下は実際に電源設定を変更する検証。
AntiSleepと旧版Capsomniaを終了し、開始時点のSleepDisabled=0を確認してから実行する。
既存の設定を保護するため、開始時点の状態が違う場合は検証を中止する。

```sh
python3 scripts/verify-menu-bar.py dist/AntiSleep.app test-results/menu-bar-check.json
python3 scripts/verify-toggle.py dist/AntiSleep.app test-results/toggle-check.json
python3 scripts/verify-system.py dist/AntiSleep.app test-results/system-check.json
```

消灯試験は、70秒間キーボード・マウス・タッチパッドに触れずに待てる場合に限り、最後に行う。
途中で点灯した場合は失敗として記録し、消灯試験の成功とは扱わない。

```sh
python3 scripts/verify-system.py dist/AntiSleep.app test-results/screen-off-check.json --screen-off
```

verify-system.pyは、検証専用の明示オプションで保護をONにする。通常起動の仕様はOFFのまま。

実際のふた閉じ試験は、パネルでONを確認した状態で対象PIDを指定して開始する。
ARMEDと表示されたら、ふたを閉じて90秒待ってから開く。設定の変更・アプリの再起動・画面の前面表示は行わない。

```sh
python3 scripts/verify-closed-lid.py --pid <AntiSleep本体のPID>
```

生ログ・画像・JSONはtest-results/に置き、Gitには含めない。
