## 0.2.4：右上の終了ボタンと解除確認の強化

パネル右上に×を追加し、右クリックの「終了」と同じ復元付き終了処理へ接続した。
パネル外へのクリックは従来どおり表示だけを閉じる。切り替え・終了処理中は操作を無効化し、
重複した終了要求も一つにまとめる。

設定変更は復元監視プロセスへパイプで依頼し、監視内で直列に実行する。
本体が設定変更の途中で落ちても、設定変更を終えてからEOFを検出して復元する。
応答先が消えてもSIGPIPEで監視が落ちないようにした。
設定コマンドの成功・失敗だけで判断せず実値を確認し、失敗応答でも変更済みの可能性を追跡する。
正常終了では、設定復元・IOKit要求の解除・監視プロセスの停止を確認できるまで終了しない。
監視はTERM・INT・HUPを無視し、異常終了後の復元に失敗しても5秒待って再試行を続ける。

- 状態遷移29項目が成功。設定変更済みの失敗応答、復元の見かけ上の成功、
  IOKit要求の解除失敗、監視停止失敗、終了失敗後の再試行を含む。
- 「変更済みの失敗応答を復元対象として追跡する」修正を外した退行版では、該当テストが失敗した。
- Releaseビルド、アプリとヘルパーのdeep / strict署名検証が成功。
- 実際のヘルパーで、外部解除後の再適用、監視強制終了後の再起動、通常終了、
  本体のSIGKILL後の設定復元を確認した。
- 実際の電源ボタンactionでOFF→ON→OFF→ON、終了と再起動OFF、
  メニューバー可視性・右側配置・通常時のパネル非表示を確認した。
- 検証用コピーのパネルを実際に開き、×の座標へのマウスイベントをアプリ自身のキューに投入。
  OFF・ONの両方で終了し、SleepDisabled=0・本体の防止要求なし・監視プロセスなしを確認した。
- 復元を一度失敗させた検証用コピーで、終了の中止とボタンの再有効化、再度の×操作による復元を確認。
  この障害試験ではアラート表示を記録に置き換えており、実際のアラート操作とは区別する。
- 電源設定をファイルへ置き換えた監視の試験で、TERM・INT・HUP後も生存し、
  コマンドが成功応答でも実値が4回戻らない条件から、5回目で復元して終了することを確認。
- 同じ模擬監視でON変更に遅延を入れ、変更開始後に入力・応答先の両方を閉じた。
  変更完了後に復元し、遅延したONが復元後に残らないことを確認した。
- OFF・ONのパネルをPNG化し、右上の×と既存内容が重ならず表示されることを目視確認。
  物理マウスによる操作やOS全画面の画像取得ではない。
- `/Applications/AntiSleep.app`を0.2.4へ更新し、同じ切り替え・終了・再起動OFFと
  メニューバー検証を再実施した。配布ZIPの破損検査・署名検証も成功した。

途中の試行では実機試験を重ねて起動したため、画面側の試験が開始条件チェックで中止された。
また、監視通信を追加した最初の試行で、成功応答と読み取り長が合わず応答待ちになる不具合を検出した。
本体の終了後に監視が復元したことを確認し、応答を固定1バイトに修正して実機試験を順番にやり直した。
これらの途中試行は合格結果に含めていない。

物理的なふた閉じ・消灯処理は変更していないため再試験していない。
OSクラッシュ・強制電源断・監視を含む全プロセスのSIGKILLや、ヘルパーが復元不能な条件での
無条件な解除は保証しない。元からSleepDisabled=1だった設定は引き続き維持する。

消灯試験は、70秒間キーボード・マウス・タッチパッドに触れずに待てる場合に限り、最後に行う。
途中で点灯した場合は失敗として記録し、消灯試験の成功とは扱わない。

```sh
python3 scripts/verify-system.py dist/AntiSleep.app test-results/screen-off-check.json --screen-off
```

verify-system.pyは、検証専用の明示オプションで保護をONにする。通常起動の仕様はOFFのまま。

実際のふた閉じ試験は、パネルでONを確認した状態で対象PIDを指定して開始する。
ARMEDと表示されたら、ふたを閉じて90秒待ってから開く。設定の変更・アプリの再起動・画面の前面表示は行わない。

```sh
python3 scripts/verify-closed-lid.py --pid <AntiSleep本体のPID>
```

生ログ・画像・JSONはtest-results/に置き、Gitには含めない。
